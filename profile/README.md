# ailab-co

> 三个人 + 三套 AI Agent 的协作组织。口语里我们叫它「**AI 实验室**」。

## 为什么有这个组织

我们三个（`cabin` / `xiehai` / `shuai`）跨时区、沟通不高频，但各自都在用 AI 做深度调研和研发。
这种工作方式会产生**大量结论和判断**，而它们的默认命运是烂在各自的电脑和聊天记录里。

这个组织解决三件具体的事：

| 要防的 | 怎么防 |
|---|---|
| 三个人都很努力，但半年后成果拼不到一起 | `hq/bets.md` 顶部的 **North Star** —— 一句话，用来否决跑偏的方向 |
| 两个人各自深挖同一件事两周 | **Bet 认领表** —— 开工前先看谁在挖什么 |
| 有人基于一个已经死掉的结论继续投入 | 每条结论带**保鲜期**，过期即视为待验证 |

## 三个仓

| 仓 | 是什么 |
|---|---|
| ⭐ **[`hq`](https://github.com/ailab-co/hq)** | **协作中枢。先读这个。** 规范 / 决策日志 / 结论库 / Bet / 项目登记表 |
| [`shortdrama`](https://github.com/ailab-co/shortdrama) | 中东出海 AI 短剧 |
| `aigc-pipeline` | AIGC 内容生产底座（待迁入） |

**分界铁律**：`hq` 管「为什么 / 是什么 / 谁负责」，项目仓管「怎么跑」。
判据——**一个文件如果会被执行，它就不属于 hq。**

## 两个核心概念

| | **Bet**（赌注） | **Issue** |
|---|---|---|
| 回答什么 | 该不该做 / 能不能行 | 谁去做这件确定的事 |
| 产出 | 一个**判断** | 一个**东西** |
| 时长 | 2–4 周 | 半天 – 3 天 |
| 数量 | 全局 ≤6 | 不限 |
| 住哪 | `hq/bets.md` | 项目仓 Issues |

**判据：做完之前你就知道结果长什么样 → Issue。做完才知道 → Bet。**

⭐ Bet 的判定只有三态：**成立 / 否证 / 未完成**。
**「否证」等价于成功** —— 快速排除错误方向是我们最核心的价值，如实报告负面结论比报告成功更重要。

## 第一天怎么开始

```bash
git clone https://github.com/ailab-co/hq.git ~/Documents/ailab-co/hq
cd ~/Documents/ailab-co/hq
bin/sync        # 拉取 + 打印「谁在挖什么 / 什么结论该复核了 / 近期动静」
```

然后 10 分钟读完 `hq` 里这五个文件：

1. `README.md` —— 日常怎么用
2. `AGENTS.md` —— 规则本体（**你的 Agent 也读它**：Claude Code 走 `CLAUDE.md` import，Codex 原生读）
3. `bets.md` —— 我们现在在赌什么、谁认领了什么
4. `GOVERNANCE.md` —— 谁对什么有最终决策权
5. ⭐ `decisions/0003` —— 这套机制**为什么**这么设计（八条反常规选择 + 每条的翻案条件）

## 这套机制本身是可以被推翻的

`decisions/0003` 列了八条**反常规**的设计选择，每条都带「什么情况下应该翻案」。

按 `GOVERNANCE.md`：**技术架构与协作机制的最终决策权在 `xiehai`**，不需要先问发起人。
开一个 RFC 即可 —— **3 个自然日无异议自动通过**。

发现规则挡路了，改它，别绕它。
